# Локальная работа бота

Бот запускается на этом Mac, использует long polling Telegram и не требует публичного порта или webhook. Он читает Waviot, ведёт проверки в подключённой рабочей группе и отвечает в личных чатах зарегистрированных сотрудников. Регистрация, админка и Docker описаны в [инструкции развёртывания](deployment.md). Автоматические тревоги о расходе и связи пока выключены: готовое потребление газа и воды и семантика свежести ещё проверяются. Локальный запуск не означает завершения приёмки рабочего мониторинга.

## Настройки и первый запуск

В `.env` нужны `WAVIOT_API_KEY`, `WAVIOT_HOUSE_ID` и `TELEGRAM_BOT_TOKEN`. Токены не передаются через аргументы команд, сообщения или репозиторий. Пример имён настроек — `.env.example`. `BOT_TIMEZONE=Europe/Moscow`, `BOT_DATABASE=artifacts/runtime/state.sqlite3`, `BOT_LIVE_ALERTS=false`. Попытка включить автоматические тревоги сейчас отклоняется с объяснением.

```sh
.venv/bin/pip install --no-build-isolation --no-deps .
.venv/bin/waviot-bot check
.venv/bin/waviot-bot run
```

`check` проверяет токен и наличие webhook без отправки сообщений. Существующий webhook не удаляется: запуск остановится с объяснением. Доступ выдаётся через приглашения из админки, а не через старую startup-ссылку или `TELEGRAM_CHAT_ID`. Существующая привязка личного чата не заменяет регистрацию сотрудника. Случаи ведутся в одной рабочей группе, подключённой командой `/connect` с одноразовым кодом.

Не запускайте второй polling-процесс с тем же токеном. Файловая блокировка защищает от двух экземпляров с одной базой; Telegram 409 может означать другой экземпляр на другом компьютере. База проверяет принадлежность конкретному боту.

## Команды и проверки

| Команда | Результат |
|---|---|
| `/status` | Состояние локального процесса, сбор, открытые проверки, неясная доставка |
| `/house` | Покрытие квартир принятого реестра ресурсами; источник данных явно указан |
| `/flat 211` или `211` | Прямой запрос последних показаний газа, воды и электричества квартиры с номерами приборов, единицами и датами |
| `/scan` | Новый последовательный сбор метаданных всего дома; прогресс в `/status` |
| `/candidates` | Старые метки газа, без утверждения нулевого расхода или причины; можно вручную создать проверку |
| `/cases` | Открытые проверки с постраничными кнопками |
| `/history ID` | Сохранённые авторы, время и результаты всех действий |
| `/demo` | Вымышленная тестовая карточка; не относится к реальному прибору |
| `/delivery` | Отправки с неопределённым результатом |

Частые команды доступны через кнопку «Меню» Telegram и постоянную клавиатуру под полем ввода: «📊 Показания», «📋 Случаи», «🔎 Кандидаты», «🏠 Дом», «🔄 Обновить», «⚙️ Статус», «❓ Помощь». Кнопки выполняют те же команды; «Показания» просит номер квартиры. Если клавиатура скрыта, восстановите её через `/help` или `/menu`. Меню команд регистрируется только для подключённого чата.

Кнопка принятия назначает ответственного; при повторном принятии сохраняется история смены. «Неисправность» и «Причина неизвестна» оставляют случай открытым. «Нормальная ситуация» закрывает его; «Устранено» доступно после подтверждения неисправности. Для результатов нужно ответить на конкретное приглашение бота с пояснением. Ответ другого автора и ответ на устаревшую версию не изменяют проверку. Старые и повторные нажатия не повторяют переход.

Карточка случая, список и дневная сводка используют HTML-выделение и эмодзи. Карточка показывает квартиру и корпус, заводской номер газового счётчика, последнее известное показание с единицей и датой, статус, ответственного, основание, результат проверки, пояснение и автора последнего действия. Причина обращения выводится отдельно: «Данные счётчика не поступают» или «Нет расхода», в зависимости от типа случая; это не диагноз неисправности. Неизвестное значение обозначается как «нет данных», а не ноль. Даты выводятся в GMT+3 без подписи зоны. Кнопка «📜 История» доступна и для закрытого случая. Длинные поля в карточке сокращаются с многоточием, полный текст сохраняется в истории. Динамические значения экранируются; состояние и версия случая при изменении оформления не меняются.

Сведения о приборе сохраняются со случаем; у открытых случаев они обновляются после сбора метаданных всего дома. У закрытых остаются сохранённые сведения. Обновление показаний не меняет результат сотрудника и не создаёт новых событий в истории действий. Учебные случаи содержат явно вымышленные квартиру, номер и показание. Новые поля и подписи не включают автоматические тревоги: кандидаты по старой метке по-прежнему требуют ручной проверки свежести данных API.

Команда `/flat` подсказывает, как ввести номер квартиры. Запрос принимает только квартиры из реестра подключённого дома и доступен только подключённому чату. Ответ состоит из блоков с эмодзи, выделенными значениями, номерами приборов и датами. По электричеству показывается только общий итог из суммарного регистратора, без тарифов; если итога нет, он остаётся неизвестным и не вычисляется из тарифов. Даты ответа всегда приводятся к GMT+3, подпись часового пояса и пояснение о расходе не выводятся. Старые метки помечаются, отсутствие значения, даты или привязки прибора указывается явно. Повторный запрос снова читает Waviot. Число в ответ на приглашение о причине остаётся пояснением к проверке, а не запросом квартиры.

Сбор при старте и каждые шесть часов читает дерево и метаданные всех квартир с паузой минимум секунду. Неполное дерево не заменяет принятый реестр. Ошибки сбора показываются отдельно; временные ряды не преобразуются в расход и пропуски не заменяются нулём. Начальный сохранённый аудит используется только с явной пометкой источника до завершения живого сбора. Доступные сейчас кандидаты формируются по старой метке значения API, а не по подтверждённому сроку радиомолчания.

## Доставка и восстановление

Входящие обновления сохраняются до подтверждения offset; изменение проверки и задание на карточку фиксируются транзакционно. Дневная сводка включает открытые проверки с пометкой тестовых. Напоминания относятся только к неназначенным; время дома 09:00–18:00. После ночи формируется актуальная сводка без накопления старых дневных копий.

429 переносит отправку по `retry_after`. Неясный результат `sendMessage` не повторяется вслепую. После проверки чата владелец может указать:

- `/resolve ID sent MESSAGE_ID` — сообщение найдено, связать запись с его ID;
- `/resolve ID retry` — владелец проверил отсутствие сообщения и просит повторить отправку.

Удалённая карточка заменяется с тем же номером проверки при следующем обновлении. История хранится в базе, удаление сообщения её не удаляет.

## Процесс и резервная копия

```sh
.venv/bin/waviot-bot status
.venv/bin/waviot-bot stop
.venv/bin/waviot-bot backup --output artifacts/backup-new.sqlite3
```

`stop` посылает сигнал действующему локальному экземпляру; активный сбор завершится при ближайшей проверке остановки. Для перезапуска после изменения исходников сначала остановите процесс, переустановите пакет и выполните `run`. В текущем сеансе исполнитель может запустить тот же процесс в фоне с журналом `artifacts/runtime/bot.log`.

Резервная копия создаётся средствами SQLite в новый файл с правами `600`. Для проверки восстановления используйте отдельный путь `BOT_DATABASE` и команду `status`, **не запускайте второй polling**. После остановки основного процесса можно запускать восстановленную базу с тем же токеном; сохранённые offset и подтверждённые отправки предотвращают обычное повторение.

Mac должен оставаться включённым, с доступной сетью. Автозапуск при включении, внешний контроль heartbeat, серверное развёртывание, массовая корреляция реальных тревог и групповая приёмка двумя участниками ещё не выполнены. Секреты и реальные технические данные остаются в игнорируемых `.env` и `artifacts/`.
