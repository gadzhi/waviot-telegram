# Docker и админка сотрудников

Проект запускается локально через Compose; на сервере используется тот же образ. Публичное развёртывание в этой задаче не выполняется. Автоматические тревоги по расходу остаются выключенными.

## Первый запуск с пустой базой

1. Заполните `.env` по `.env.example`. Реальные ключи не входят в build context. Сохраните принятый `audit-scope.json`: его нужно перенести в постоянное хранилище перед рабочим сбором.
2. Подготовьте локальный каталог, соберите образ и создайте администратора:

```sh
mkdir -p artifacts
docker compose build admin
docker compose run --rm --no-deps admin waviot-admin bootstrap
docker compose create admin
docker compose cp admin:/data/admin-onboarding.html artifacts/admin-onboarding.html
```

Файл первого входа содержит логин и сгенерированный пароль. Права файла — `600`. Он показывает секреты только локально; в консоль они не выводятся. Перенесите пароль в менеджер паролей. После настройки удалите обе копии onboarding-файла (на компьютере и в `/data` контейнера). Сам файл для работы системы не нужен. Не публикуйте его через веб-сервер и не отправляйте в чат.

3. Скопируйте принятый реестр в volume от имени пользователя приложения:

```sh
docker compose run --rm --no-deps -v "$PWD/audit-scope.json:/import/scope.json:ro" admin python -c "from shutil import copyfile; copyfile('/import/scope.json','/data/audit-scope.json')"
docker compose up -d --no-build admin bot
docker compose ps
```

Админка: `http://127.0.0.1:8000`. Это локальный HTTP; серверный публичный доступ включается отдельно с HTTPS. Первый администратор — `admin`; другое имя задаётся `bootstrap --username ИМЯ --output /data/новый-файл.html`. Смена/восстановление администратора выполняются из терминала сервера созданием нового администратора и отключением старого через Django ORM; автоматического сброса пароля по телефону нет.

## Переход с текущего локального процесса

Сначала остановите прежний polling и создайте **новую** резервную копию. Не запускайте контейнер с тем же Telegram-токеном параллельно локальному процессу, даже если базы разные.

```sh
.venv/bin/waviot-bot stop
.venv/bin/waviot-bot backup --output artifacts/before-docker.sqlite3
docker compose build admin
docker compose run --rm --no-deps -v "$PWD/artifacts/before-docker.sqlite3:/import/state.sqlite3:ro" admin waviot-admin import-state --source /import/state.sqlite3
```

Импорт откажется заменять существующую целевую базу. Он выполняет SQLite backup и проверку целостности, сохраняет inventory, очередь Telegram, случаи и историю; затем выполните bootstrap и копирование scope из первого раздела. Старая привязка личного чата не даёт прав сотрудника: владелец также регистрируется через приглашение. Старые карточки останутся в личном чате; после подключения группы бот создаст там актуальные карточки с прежними номерами случаев.

## Регистрация и группа

В админке откройте «Сотрудники», введите имя и телефон. Код показывается в ответе один раз, действует 24 часа и хранится только как SHA-256 хеш. Код содержит 16 случайных символов, поэтому не является коротким PIN. Передайте его лично сотруднику. В личном чате сотрудник нажимает «Поделиться номером» и вводит код. Пересланный чужой контакт, контакт без Telegram user_id, несовпадающий номер, использованный или просроченный код не допускают регистрацию. После пяти попыток одного аккаунта — пауза 15 минут; есть общий лимит попыток. Контакт действует 15 минут. Оба шага повторяются при перепривязке.

«Отключить» немедленно запрещает команды, callbacks и отложенные личные ответы. «Отвязать и выдать новый код» сначала отзывает старый Telegram-аккаунт. История действий сохраняется. Администратор управляет доступом через браузер; доступ администратора к Telegram не возникает автоматически.

В разделе «Рабочая группа» создайте одноразовый код на 24 часа. Зарегистрированный сотрудник добавляет бота в группу и отправляет `/connect КОД`. Сотрудник должен быть администратором группы и писать от своего аккаунта, не анонимно. Боту достаточно быть участником; Telegram разрешает ему читать команды и ответы на собственные сообщения при включённом Privacy Mode. Проверка прав сотрудника использует список администраторов `getChatAdministrators`; отдельные права администратора для самого бота не требуются. В группе могут нажимать кнопки только зарегистрированные сотрудники. Все участники группы видят её сообщения; за состав группы отвечает её администратор.

Показания квартир доступны только в личных чатах сотрудников; случаи — в группе. После отключения группы новые сообщения туда не отправляются. Старые сообщения Telegram нельзя отозвать отключением доступа в приложении. При переподключении сохраняются история и номера случаев, но создаются новые сообщения карточек. Сообщения и неопределённые отправки прежнего подключения не привязываются к новой группе.

## Публичный адрес на сервере

В серверном `.env` задайте `ADMIN_DOMAIN=admin.example.org`, направьте DNS на сервер и откройте порты 80/443. Администратор с сильным уникальным паролем должен быть создан **до** публикации.

```sh
docker compose -f compose.yaml -f compose.public.yaml build
docker compose -f compose.yaml -f compose.public.yaml up -d
```

Caddy получает сертификат и перенаправляет HTTP на HTTPS. Внешний прокси слушает 80/443; backend админки остаётся привязанным к localhost на хосте. В public-режиме Django требует HTTPS, проверяет host/origin, использует secure cookies, CSRF и HSTS. Вход в админку выполняется по логину и паролю, без OTP. Для защиты форм используется CSRF; `Referrer-Policy: same-origin` сохраняет корректную работу входа в Firefox и других браузерах. Десять попыток входа за 15 минут ограничены по аккаунту и адресу подключения. Приложение не доверяет произвольным X-Forwarded-For.

Нельзя ставить `ADMIN_PUBLIC=false` на публичном адресе или публиковать порт backend на `0.0.0.0`. TLS/ACME и вход через реальный домен проверяются при серверном развёртывании; локальная проверка их не заменяет.

## Проверки

```sh
docker compose --profile test build tests
docker compose --profile test run --rm --no-deps tests
```

Тестовый сервис не получает `.env`, не имеет сети и проверяет Linux-контейнер, а не другие ОС. Публичную конфигурацию проверяйте с `ADMIN_PUBLIC=true` через Django `check --deploy`. HSTS включён для самой админки; распространение на поддомены и preload требуют отдельного решения после выбора домена.

## Состояние, остановка и копии

Бот и админка работают под UID/GID `10001`, с read-only root, без Linux capabilities. SQLite и ключ админки сохраняются в named volume `waviot_runtime`. Образы закреплены digest, Python-зависимости — версиями в lock-файлах. Контейнер бота не имеет опубликованных портов. `container_name` запрещает масштабирование сервиса бота; файловая блокировка защищает одну базу, а защита от запуска с копией базы — организационная: один токен, один polling.

```sh
docker compose ps
docker compose stop bot admin
docker compose start bot admin
```

Для контейнера используйте `docker compose stop`, **не** команду `waviot-bot stop` на хосте: PID из базы принадлежит namespace контейнера. Grace period — 90 секунд. Healthcheck бота читает heartbeat без сети и без записи в базу. Ошибка Telegram 403 для одного адресата не останавливает всех сотрудников.

Для согласованной полной резервной копии остановите оба сервиса и сохраните volume целиком: `state.sqlite3`, `admin.sqlite3`, `admin-secret.key`, `audit-scope.json` и возможные SQLite journal-файлы. Держите копии с ограниченными правами: они содержат телефоны, настройки администратора и историю. Перед обновлениями делайте новую копию; при восстановлении не запускайте второй polling. `docker compose down` сохраняет volume; **не используйте `down -v`**, если хотите сохранить данные.
