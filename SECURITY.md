# Безопасность и приватность

## Что нельзя публиковать

`.env` и его копии, ключ Waviot, токен Telegram, пароль первого входа, ключ Django, SQLite, резервные копии, журналы, скриншоты личного кабинета, исходные документы интеграции и реальные ответы API. Адреса домов, номера квартир вместе с телеметрией, телефоны сотрудников, номера приборов и ID объектов тоже могут раскрывать сведения конкретной эксплуатации.

`.gitignore` предотвращает обычное добавление новых файлов, но **не удаляет уже закоммиченные данные из истории**. Docker build context ограничен разрешёнными файлами; рабочие данные хранятся отдельно в volume.

## Перед публикацией

1. Просмотрите состав Git-файлов и каждый коммит, который будет отправлен.
2. Проверьте всю публикуемую историю сканером секретов, а не только текущую версию:

```sh
gitleaks git --log-opts=--all --redact=100 --no-banner .
gitleaks dir --redact=100 --no-banner .
```

Сканирование каталога запускайте в очищенной копии. Рабочий каталог намеренно содержит локальные секреты и отчёты, которые не должны уходить в GitHub.

3. Отдельно проверьте адреса, телефоны, локальные пути, имена, номера приборов и metadata коммитов. Gitleaks не является проверкой всех персональных данных.
4. Сверьте содержимое с локальными ключами без вывода их значений в консоль.
5. Проверьте зависимости и тесты. Не публикуйте отчёты сканера с неотредактированными секретами.

Эта публичная версия подготовлена отдельно от рабочей Git-истории. Результаты аудита реального объекта и локальная история разработки в неё не включены. В тестах используются синтетические номера; примеры телефонов взяты из диапазона [NANPA 555-0100–555-0199](https://www.nanpa.com/numbering/555-line-numbers), зарезервированного для вымышленных номеров.

## Защита работающего сервиса

- Для публичного доступа используйте HTTPS-конфигурацию, сильный уникальный пароль и ограниченный доступ к серверу. Вход администратора — по логину и паролю, без OTP, по принятому дизайну.
- Не публикуйте порт backend на всех интерфейсах. Не отключайте CSRF ради входа из iframe или страницы с `Origin: null`.
- Код приглашения сотрудника одноразовый, на 24 часа, связан с телефоном. Контакт принимается только от владельца Telegram-аккаунта. Перепривязка выполняется администратором.
- Отключение сотрудника запрещает новые действия и отложенные личные ответы, но не удаляет сообщения, уже видимые ему в Telegram. Состав рабочей группы проверяет её администратор.
- SQLite, настройки администратора и резервные копии содержат чувствительные данные. Храните их с ограниченными правами; не загружайте как артефакты публичного CI.
- Обновляйте зависимости, базовые образы и резервные копии. Один Telegram-токен должен использовать один polling-процесс.

## Если секрет попал в Git

Сначала отзовите или перевыпустите секрет у его владельца. Удаление строки или коммита не делает утёкший токен безопасным. Затем очистите публикуемую историю и перепроверьте её. Не помещайте секрет или приватные данные в публичный issue при сообщении о проблеме.

Автоматическое сканирование уменьшает риск утечки, но не гарантирует отсутствие всех чувствительных данных и не заменяет проверку эксплуатационной конфигурации.
